# i18n (Paraglide)

Never hardcode user-facing text.

```svelte
<script lang="ts">
  import { m } from '$messages';
</script>

{m.site_name()}
{m['radio.title']()}
{m['track_editor.validate.waypoint_invalid']({ index: 1, key: 'x', type: 'number' })}
```

- Bracket syntax for namespaced keys; parameterized messages take one object.
- Works in `.ts` too (zod error factories, `src/hooks.server.ts`).
- Import from `$messages`. `$lib/paraglide/messages` is used directly only where the alias can't be (`src/hooks.server.ts`, `src/routes/(map)/+layout.svelte`) and in `vi.mock` targets.

## Adding messages

1. Add the key to `messages/en.json` (base locale), then `th` and `id`.
2. `messages/{ms,tl,vi}.json` are empty stubs — `project.inlang/settings.json` parks those locales under `__unused_asean_locales`, so they are not compiled. Active locales are **en, th, id**.
3. The Vite plugin recompiles on dev/build; `pnpm paraglide:compile` regenerates manually. Never edit `src/lib/paraglide/`.
4. Missing keys fall back to `en`.

## Runtime

- Strategy `['custom-svelteReactiveLocale', 'baseLocale']` with `localStorageKey: 'siteLocale'` (`vite.config.ts`); the strategy itself is registered client-side in `src/routes/+layout.svelte` via `defineCustomClientStrategy`, reading `siteLocale.l` from `src/lib/components/Locale/locale.svelte.ts`.
- The switcher UI is `src/lib/components/Navbar/SettingsMenu.svelte`.
- `src/hooks.ts` `reroute` strips locale prefixes (`deLocalizeUrl`), so routes never see locale segments; `paraglideMiddleware` fills `%lang%`/`%dir%` at prerender time.
- `getMtLocale` (`src/lib/utils/getMtLocale.ts`) picks a translation out of a game-name table — it is unrelated to date formatting.
- Non-Latin scripts need a font entry in `src/hooks.server.ts`.
- The lefthook pre-commit codegen is globbed to `src/*`, so a commit touching only `messages/*.json` does not recompile — run `pnpm paraglide:compile` yourself.
