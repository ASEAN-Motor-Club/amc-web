# i18n (Paraglide)

Never hardcode user-facing text.

```svelte
<script lang="ts">
  import { m } from '$messages';
</script>

{m.site_name()}
{m['radio.title']()}
{m['track_editor.validate.waypoint_invalid']({ index: 1, key: 'x', type: 'number' })}
```

Bracket syntax for namespaced keys; parameterized messages take one object. This works in `.ts` too (zod error factories, head tags).

## Adding messages

1. Add the key to `messages/en.json`, then to every locale listed under `locales` in `project.inlang/settings.json` — locales parked in the `__unused_*` list are not compiled, so leave them alone. Missing keys fall back to `en`.
2. The Vite plugin recompiles on dev/build; `pnpm paraglide:compile` does it manually. Never edit `src/lib/paraglide/`.
3. `messages/*.json` is outside the pre-commit glob, so a messages-only commit regenerates nothing — compile before committing.

## Runtime

- The locale strategy is configured in `vite.config.ts` and registered client-side in the root layout, backed by the reactive state in `src/lib/components/Locale/`.
- `src/hooks.ts` `reroute` strips locale prefixes, so route files never handle locale segments.
- `getMtLocale` picks a translation out of a game-name table; it has nothing to do with dates.
